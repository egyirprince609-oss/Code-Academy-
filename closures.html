Closures & Scope Chain

Closures are the #1 concept that separates junior from senior JavaScript developers. Master this and you can answer 80% of JS interview questions. This is how data privacy, function factories, and module patterns work in JavaScript.

🎯 What is a Closure?

Definition
A closure is a function that remembers and accesses variables from its outer scope even after the outer function has returned. Think of it like a function carrying a "backpack" of all variables it needs from its parent scope. The function + its backpack = closure.
Basic Closure Example
function outer() { let count = 0; // variable in outer scope function inner() { count++; // inner function accesses outer variable console.log(count); } return inner; // return the inner function } const counter = outer(); // outer() runs and returns inner counter(); // 1 counter(); // 2 counter(); // 3
Line 2: let count = 0

This variable is declared in outer function's scope. Normally when outer() finishes, count would be deleted from memory. But because inner function references count, JavaScript keeps it alive.

Line 4-7: function inner()

Inner function has access to count even though count is not declared inside inner. This is "lexical scope" - functions can access variables from outer scopes where they were defined.

Line 10: return inner

We return the inner function itself, not inner(). When outer() finishes, normally count would be garbage collected. But because we returned inner, and inner uses count, count stays in memory. This is the closure.

Line 13-15: counter()

Every time we call counter(), it remembers count from previous calls. count is not reset to 0. This is why closures are used for data privacy - count is private and cannot be accessed directly from outside.

💡 Why Closures Matter?

1. Data Privacy

Variables inside closure cannot be accessed directly. Only inner function can modify them. This creates private variables like in other programming languages.

2. Function Factories

Create functions with preset configurations. Each function remembers its own settings from when it was created.

3. Module Pattern

How libraries like jQuery work. Public methods exposed, private variables hidden inside closure.

4. Event Handlers

When you add event listener in loop, closure ensures each handler remembers correct value of loop variable.

⚡ Live Example: Function Factory

Real Use Case
Function factories create multiple functions with different settings. Each function remembers its own configuration through closure.
Function Factory Code
function createMultiplier(multiplier) { // multiplier is remembered by closure return function(number) { return number * multiplier; }; } const double = createMultiplier(2); // multiplier = 2 const triple = createMultiplier(3); // multiplier = 3 console.log(double(5)); // 10 console.log(triple(5)); // 15

⚠️ Common Mistake: Loop with var

Problem with var in loop
// WRONG - all functions print 3 for(var i = 0; i < 3; i++) { setTimeout(function() { console.log(i); // i is 3 for all }, 1000); } // CORRECT - use let or closure for(let i = 0; i < 3; i++) { setTimeout(function() { console.log(i); // 0, 1, 2 }, 1000); }
Why this happens: var is function-scoped, not block-scoped. All 3 timeout functions share same i variable. By the time timeout runs, loop finished and i = 3.

Solution: Use let which is block-scoped, or wrap in IIFE to create new scope for each iteration. This is classic closure interview question.
