⚡ Promise.all vs Promise.allSettled vs Promise.race

When to Use Each
Three ways to handle multiple promises. Choose the right one or your app will break in production.
Promise.all
Use when: All requests must succeed
Fails: If 1 fails, all fail fast
Returns: Array of results
Promise.allSettled
Use when: Need all results even if some fail
Fails: Never fails
Returns: Array of {status, value/reason}
Promise.race
Use when: Need fastest response
Fails: If fastest fails, race fails
Returns: First settled result
Code Comparison
// Simulate 3 API calls const api1 = () => new Promise(res => setTimeout(() => res('User Data'), 1000)); const api2 = () => new Promise(res => setTimeout(() => res('Posts Data'), 2000)); const api3 = () => new Promise((res, rej) => setTimeout(() => rej('Error!'), 1500)); // Promise.all - fails fast Promise.all([api1(), api2(), api3()]) .then(results => console.log(results)) .catch(err => console.log('Failed:', err)); // Error! after 1.5s // Promise.allSettled - waits for all Promise.allSettled([api1(), api2(), api3()]) .then(results => console.log(results)); // All 3 results after 2s // Promise.race - first to finish Promise.race([api1(), api2(), api3()]) .then(result => console.log(result)); // User Data after 1s
Line 9-12: Promise.all

Starts all 3 APIs in parallel. api3 fails at 1.5s, so Promise.all rejects immediately. api2 result is lost even though it would succeed at 2s. Use when all data is required.

Line 15-17: Promise.allSettled

Waits for all 3 APIs to finish regardless of success/failure. Returns array with status: 'fulfilled' or 'rejected'. Use for dashboard where partial data is better than no data.

Line 20-22: Promise.race

Returns result of whichever promise settles first. api1 wins at 1s. If api1 failed, race would reject at 1s. Use for timeout patterns or fastest server selection.

🔄 Async Generators & for await...of

What are Async Generators?
Async generators let you yield values asynchronously one by one. Perfect for streaming data, pagination, or processing large datasets without loading everything in memory.
Async Generator Example
async function* fetchPages() { let page = 1; while(page <= 3) { // Simulate API call const data = await fetchData(page); yield data; // Pause and return data page++; } } async function processPages() { for await (const page of fetchPages()) { console.log('Processing:', page); } } function fetchData(page) { return new Promise(res => setTimeout(() => res(`Page ${page} data`), 1000) ); }
Line 1: async function*

The * makes it a generator. async makes it return promises. Combined = async generator. Function pauses at yield and resumes when next() is called.

Line 5: yield data

Pause function and return data. Next iteration resumes from here. This is memory efficient - only one page in memory at a time.

Line 10: for await...of

Special loop for async iterables. Waits for each yield before continuing. Without await, you'd get promises instead of data.

🛡️ Production Error Handling Pattern

Safe Async Wrapper Pattern
// Wrapper that never throws async function safeAsync(promise) { try { const data = await promise; return [null, data]; // [error, data] } catch(error) { return [error, null]; // [error, data] } } // Usage async function loadUser() { const [err, user] = await safeAsync(fetchUser()); if(err) { console.log('Failed:', err); return; } console.log('User:', user); } // This pattern is used by Go language. // No try/catch needed everywhere.
Why this pattern: Instead of try/catch everywhere, wrap promises in safeAsync. Always returns array [error, data]. If error is null, success. If data is null, failed. Cleaner code, no nested try/catch.
