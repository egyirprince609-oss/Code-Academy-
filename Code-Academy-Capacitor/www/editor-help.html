COMPLETE WORKSPACE GUIDE

Know your editor. Keep your focus.

The Code Academy Editor is a browser-based workspace for learning and building code. Its main goal is to keep your code area broad, hide secondary panels until needed, and clearly distinguish supported browser execution from languages that still require a compiler or server service.

1. Workspace layout

The top bar contains back navigation, project name, create/save, run and share. The toolbar holds format, download, backup, import, export and console controls. Use the explorer button to reveal projects and files; close it to expand the editor area. On phones, the explorer slides over the work area instead of permanently taking its width.

2. Files and folders

Use New file or New folder to organize files into paths such as src/app.js. The extension controls syntax highlighting. Tabs represent open files; a small change marker indicates unsaved edits. Download saves the active file, while Export ZIP packages text/code files and a project manifest into one archive.

3. Import a file, folder or ZIP

The import button accepts a Code Academy JSON backup, ZIP archive, or supported text/code file. Choose Import folder to select a directory (on devices whose browser offers directory selection). ZIP contents are extracted inside the page first; safe relative paths are validated and hidden/reserved paths are skipped before files are merged into the current project. You are asked before matching files are replaced.

For reliability, import currently allows up to 250 supported files and 650,000 characters of imported text per folder/archive. Binary assets and arbitrary package installations are not stored as text source files. Large dependency folders should be kept out of the ZIP and installed in a real build environment instead.

4. Run and preview

HTML, CSS and JavaScript projects run in a sandboxed browser preview. Press Run to open a full-width preview by default; use the shrink control to return to split view, or close preview to resume editing. JavaScript can run alone or as part of a web project. React JSX/TSX uses browser-loaded React and Babel for a practice preview, not an npm/Vite production build.

Python uses Pyodide in the browser. Its first launch loads a larger runtime over the internet. Not every native Python package is compatible with WebAssembly, and long-running work may be limited by your device's memory and speed.

5. Console and Problems

The bottom Console/Problems dock starts hidden to give code more space. Tap Console / Problems in the toolbar to open it whenever you need output or diagnostics. Runtime errors and warnings automatically reveal the Console. Syntax problems provided by Monaco appear under Problems; tap a problem row to move to its line. Use Clear to remove older output, Stop to interrupt a supported Python run, and the collapse control to hide the dock again.

6. Project saving and recovery

Projects are saved under the signed-in user's users/{uid}/projects Firestore collection using the shared authentication.js Firebase instance. Email verification and your Firestore Rules may be required. The cloud status shows whether save is pending, complete or failed. A local browser recovery copy is kept after changes so you have a chance to recover work if a save or connection fails.

Firestore stores each project as one document in this implementation. The app blocks payloads that are near the document limit and asks you to export or split large projects. This is not unlimited cloud storage. A per-file storage design would be needed for extremely large projects.

7. Sharing and metadata

Use Share to send an editor route, not your private saved project. The Web Share sheet is used where available; otherwise the URL is copied or shown for manual copying. Each editor page has its own title, description, canonical link, Open Graph image and large-image Twitter card metadata. The preview image is hosted from the same public site, so supported chat/social apps can show the image first with the title and description below it.

If a shared visitor is not signed in, the main workspace sends them to signup.html. Once they sign in, they can open the editor and save their own private projects. Sharing the editor link does not make your private source files public.

8. Supported languages and honest runtime limits

Editing and syntax highlighting are available for HTML, CSS, JavaScript, TypeScript, React JSX/TSX, Python, C, C++, Java, C#, PHP, Go, Rust, Ruby, Lua, R, Kotlin, Swift, Dart, SQL, JSON, Markdown, XML, YAML and Shell. The current run paths cover web previews, browser JavaScript, a TypeScript compiler transform, React previews, Pyodide Python, SQL through in-browser SQLite, and compiled-language examples through the external compiler service when it lists a compatible compiler. Editing support does not guarantee that a third-party service will always be available; the current compiler list is checked at run time.

9. If a library fails to load

Check the connection, reload the page, and retry once. The editor has a plain-text fallback if Monaco's CDN does not respond before its timeout. ZIP import loads JSZip only when needed; Python loads Pyodide on its first run; React preview loads React and Babel from CDNs. A failed resource should display a toast/diagnostic rather than leave you with a blank editor. If the CDN is blocked on the network, switch to a reliable connection or export your work and retry later.

Keyboard shortcuts

  • Ctrl + S: Save project.
  • Ctrl + Enter: Run the active file/project.
  • Ctrl + B: Toggle the explorer.
  • Esc: Close open dialogs and hide the explorer.

Run engines and external compilation

HTML, CSS and JavaScript use a sandboxed browser preview. Python executes in Pyodide inside a Web Worker. TypeScript is transpiled with the TypeScript compiler. SQL executes locally using an in-browser SQLite engine, so its tables are temporary and do not connect to a production database.

Compiled-language examples use the public Wandbox compiler service when a matching compiler is available. Before the first run in a browser session, the editor asks for permission because the code you submit is sent to that third-party service. Never submit secrets or confidential code. The editor checks which compiler versions the service currently advertises; if a language is missing or the service is unavailable, the error is shown clearly rather than pretending execution succeeded.

Successful program output appears in the broad Preview / Output view. Console and Problems panels remain closed during normal runs and open automatically on runtime errors or warnings. Use Console in the top toolbar to inspect messages manually.
