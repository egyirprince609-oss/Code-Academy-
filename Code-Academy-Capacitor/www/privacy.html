Code Academy Privacy Policy

At a glance

Public pages

You can read the landing page, About page, documentation, Privacy Policy, and Terms of Use without signing in.

Account data

When you use account-based features, authentication and configured Firebase services may process profile details, learning progress, and saved work.

Permissions are feature-based

Live Map can ask for location. Study or browser tools can ask for notifications. File or image controls access only the items you select.

Some tools use third parties

Depending on the feature, selected code, prompts, location/search inputs, or domains may be sent to external services to provide the requested function.

Important: the service is an evolving project. Provider configuration and feature availability can change. The notices shown in a specific tool, and the provider's own privacy terms, also matter. This policy should be kept aligned with the deployed implementation.

1. Who operates Code Academy

Code Academy is an independently developed educational project associated with its developer, Prince Egyir. The main public website is hosted at the Code Academy website. Privacy questions or requests may be sent to egyirprince609@gmail.com.

This policy covers the Code Academy website and its connected features. When you leave the site, use a third-party service, or sign into a provider, that provider may process information under its own policies.

2. Accounts and authentication

Public information pages do not require authentication. Some features ask you to sign in to associate progress, saved projects, profile settings, certificates, or notification activity with an account.

Depending on the configured sign-in method, authentication providers may process your email address, display name, profile image, phone number, provider account identifier, or other details you explicitly submit. The app can receive an authentication user identifier and the profile fields made available by the enabled sign-in method. When Google sign-in is enabled, Google handles the sign-in process; Code Academy does not ask you to give it your Google password.

Code Academy uses the details necessary to create or recognise the account, display account details, maintain account-linked progress, and protect access. The set of sign-in methods available may change with project configuration.

Google API Services Limited Use

If a feature uses Google API data, Code Academy's use and transfer of such data is intended to comply with the Google API Services User Data Policy, including the Limited Use requirements. We do not sell Google user data or use it for targeted advertising. Google API data is not accessed for unrelated purposes. Access is limited to what is needed to provide the feature, comply with law, address security issues, or as otherwise allowed by the applicable policy and consent.

3. Information that may be processed

The categories below depend on the page and the actions you choose; not every item is collected from every visitor.

Account and profile information

  • Display name, email address, provider user ID, profile image URL, phone number where used, and account creation or verification status.
  • Profile picture files or other images you select to upload, and optional certificate signature or image content if a certificate setup flow offers those fields.
  • Preferences or settings that you choose to save, such as a preferred learning language where that feature is available.

Learning and user-generated content

  • Lesson completion, course progress, quiz answers or results, XP, coins, streaks, badges, challenge history, certificate eligibility, and related learning records.
  • Projects, source code, files, notes, planner items, and other content you choose to create or save.
  • Referral identifiers or activity where referral features are enabled.
  • Information you submit to community, support, contact, sharing, or other user-input forms.

Technical and service information

Hosting, authentication, database, CDN, map, compiler, translation, AI, search, and security providers may process technical information needed to fulfil requests, such as IP address, browser/device details, timestamps, request logs, and error or security events. Code Academy may not receive every item the provider processes directly.

Do not paste passwords, private keys, API tokens, payment details, identity documents, or confidential source code into lessons, AI prompts, project files, public shares, support tickets, or external compilers.

4. Browser storage and session technologies

The site may use browser local storage, session storage, cookies, or similar mechanisms for preferences, temporary interface state, recently used items, local recovery copies, feature state, or authentication sessions. A service worker may cache selected app-shell pages and static resources so the installed experience can start or recover more reliably. Some progress or settings may remain on the current device; other records may be stored in configured Firebase services. The exact split varies by feature.

Clearing browser storage or site data can remove local preferences, drafts, recovery data, cached resources, or local progress and may sign you out. Clearing local browser data does not necessarily delete account records stored remotely. Blocking storage, service workers, or scripts may cause some pages to work incorrectly. Not every tool works offline; editors, sign-in, AI, map data, and other provider-powered features generally need a network connection.

GitHub Pages and other infrastructure providers may use technical logs to deliver, protect, or troubleshoot the website. This page does not claim that Code Academy receives every infrastructure log or that third-party providers have no logs.

5. Device permissions, uploads, clipboard, and sharing

Location permission

The Live Map feature can request browser geolocation when you activate a location control and grant permission. See the dedicated section below.

Notifications

Study planning and selected utilities can request browser notification permission. You can decline or revoke it in browser/device settings. A notification may display its text on a lock screen depending on your device configuration. Background delivery depends on the page, browser, and configured messaging services; a static web app cannot guarantee notifications while completely closed.

File and image selection

When you use an upload, import, or file-picker control, the browser gives the page access to the files you select or explicitly open. A folder import can expose files in the selected folder to the editor. Uploading a file can send it to the feature's configured storage provider. The app does not need access to every file on your device just because the page is open. If the device's picker offers a camera option, the operating system handles that picker action.

Clipboard and share sheet

Buttons to copy code, links, or content use the browser clipboard APIs where permitted. Share buttons may open the device's native share sheet or copy a link as a fallback. These actions occur after you use the relevant control and are subject to browser support.

6. Live Map, GPS, and location sharing

When you activate location on a Live Map page and grant permission, the browser may provide latitude, longitude, reported horizontal accuracy, altitude, heading, or movement information when supported by the device. Accuracy varies by device, GPS signal, buildings, and environment. It is not guaranteed to be survey-grade.

Live location updates are intended to run while the relevant page is active and the feature is running. Stop the feature or leave the page to stop that page's tracking. Do not assume the website provides persistent background tracking.

To display map tiles, search for places, show labels, or translate coordinates into an address, the page may send the relevant map tiles, search terms, or coordinates to its map/geocoding provider. The reviewed routes use OpenStreetMap-related services for some map/search functions and may use Mapbox for enhanced mapping when configured. Providers may process requests under their own terms and privacy policies.

A location share link or message can reveal precise coordinates to its recipient when you confirm sharing. Share only with people you trust. Where provided, a setting to include coordinates in notification content affects what appears in that notification. Map imagery and building outlines may be incomplete or outdated; the map is not a live camera feed of a street, house, or person.

Map preferences and any locally entered public Mapbox token, where supported by a page, may be stored in the current browser. Do not treat a public client-side map token as a secret credential; it should be restricted appropriately in the provider's configuration.

7. Editors, projects, and code execution

Code Academy includes several editor experiences. Different language routes use different execution and preview methods, and the supported approach may change.

Python browser runtimeSome Python execution uses a browser-based runtime such as Pyodide. The initial runtime files may load from a CDN. Runtime support and resource requirements vary.

Selected compiled-language editorsWhere an editor uses a service such as Wandbox or Compiler Explorer/Godbolt, code and any supplied input needed to compile or run it are sent to that external provider. Its own terms, logging, retention, and availability apply.
Saved project workspaceWhen you choose to save or load account-linked work, project files and metadata may be stored or retrieved using the configured Firebase/database services.

Some editor pages show a confirmation before sending source code to an external compiler. Read it before continuing. Do not use a third-party compiler with proprietary, confidential, or secret-containing code unless you have permission and have reviewed the provider's terms.

8. AI features, translation, browser search, and security tools

AI-assisted features

When you deliberately submit a question, prompt, code sample, or related context to an AI-assisted feature, that input may be sent to the AI provider configured for that page. The implementation may use Google/Gemini-related endpoints, OpenRouter, or another provider depending on the feature and current configuration. Providers may process prompts and technical request information under their own terms. Do not submit secrets, personal records, or confidential code.

Translation and narration

Some pages offer translation or language tools. If a translation uses a remote provider, the text you ask to translate may be sent to that provider. Speech narration may use the browser's speech synthesis implementation and available device voices. Translation quality and language availability are not guaranteed.

Browser and network utilities

When you use search, IP lookup, DNS lookup, URL/domain analysis, certificate-transparency lookup, or a safety-check function, the submitted search terms, IP address, domain, or URL may be sent to the provider used by that function. Depending on the tool, providers may include search engines, public DNS resolvers, public threat-intelligence services, URL analysis services, or public data feeds. A URL submitted for scanning may become visible to the third party you choose.

The Safe Browser workspace opens many external websites in the device browser rather than proxying their entire contents through Code Academy. External pages, searches, APIs, and downloaded content are governed by the relevant provider's own rules. Website safety signals are not a guarantee that a page is safe or malicious.

9. Service providers and sharing

We do not sell personal information. To provide functions you request, information may be processed by service providers and external destinations including, depending on feature configuration:

  • GitHub Pages or repository-hosting infrastructure for hosting public static pages and site assets.
  • Google Firebase services for authentication, database records, configured file storage, or real-time notification data.
  • Map and geocoding services such as OpenStreetMap-related endpoints and Mapbox where configured.
  • Code execution providers such as Wandbox or Compiler Explorer/Godbolt for selected compilation routes.
  • AI, translation, search, DNS, and security providers when you intentionally use the relevant page or diagnostic.
  • CDNs and asset providers that deliver fonts, editor libraries, icons, runtime files, or other page dependencies.
  • Communication providers such as email or messaging services when you contact support or choose to share information externally.

These providers process information under their own terms. We may disclose information when required by law or where reasonably necessary to protect users, investigate abuse, maintain security, enforce terms, or respond to a lawful request. Content you deliberately post in a public area or share through a public link may be visible to other people.

10. Retention and security

We retain information for as long as reasonably needed to provide the feature, preserve learning records, maintain security, resolve disputes, handle support, or comply with applicable obligations. Different providers and storage locations may have different retention periods. There is no single deletion period that applies to every record.

We use available access controls and service configurations intended to protect account data, but no website, network transmission, or storage system can be guaranteed completely secure. Do not treat Code Academy as a password manager, secret vault, secure production database, or place to store confidential credentials.

Public certificate verification records may contain a limited set of verification details so another person can check whether a credential exists in the configured registry. They are not intended to reveal the learner's private account email, internal account ID, lesson history, or private signature/photo. The fields actually visible on a specific certificate record are controlled by that page and its database configuration.

11. Your choices and privacy requests

  • Choose whether to create an account or use account-linked features.
  • Decline optional browser permissions or revoke them in your browser/device settings.
  • Use the browser controls to clear local site data, understanding that this may remove local drafts/settings but may not erase server-side records.
  • Review what you enter into external AI tools, compilers, maps, security scans, or support channels before submitting it.
  • Contact the developer to request access, correction, or deletion of personal information. Include the account email or relevant record identifier only when needed to locate the request; never send your password or one-time code.

Requests will be reviewed and handled where practical and legally required. Some records may need to be retained for security, integrity, legal compliance, or dispute resolution, and external providers control their own copies. We may need enough information to verify a request before acting on it.

12. Children and younger users

Code Academy is an educational service. A child should use account-based features with the involvement of a parent, guardian, or responsible educator where required by local law or school rules. Do not post a child's home address, live location, phone number, school schedule, or other sensitive identifying details in public content or shared project files.

If you believe personal information about a child has been submitted inappropriately, contact us using the address below and explain the concern without sending additional sensitive information.

13. Changes to this policy

This policy may change as features, service providers, or legal requirements evolve. The updated date at the top indicates the latest revision shown on this page. If a feature starts collecting or sending a new category of information, the implementation and its user-facing explanation should be updated accordingly.

14. Contact

Questions, access/correction/deletion requests, and privacy concerns may be sent to egyirprince609@gmail.com. For a technical problem, you can also visit the Support Center.

Please do not include account passwords, verification codes, API keys, private keys, or unnecessary copies of identity documents in privacy or support requests.
