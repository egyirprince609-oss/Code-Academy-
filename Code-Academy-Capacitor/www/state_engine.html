📦 Props
Data Passing
Definition: Props (properties) are read-only data passed from parent component to child component. They make components reusable and dynamic.
Props are like function arguments for React components. Parent sends data down, child receives it.

Key Rules:
• Props are read-only - child cannot modify them
• Data flows one-way: parent → child only
• Props make components reusable with different data
• Props can be any type: string, number, function, object
• If you try to change props, React throws error
Parent sends: "Hello World" → Child displays it
⬆️ Lifting State Up
State Sharing
Definition: Lifting state up means moving shared state to the closest common parent so multiple child components can access and update it.
When two components need the same state, you move that state to their parent. Parent becomes "source of truth".

Why Lift State:
• Share state between sibling components
• Keep single source of truth
• Avoid duplicate state causing bugs
• Parent controls data, children just display it
• Parent passes state + updater function as props
Parent holds state → Both children read & update it
🌐 Context API
Global State
Definition: Context API provides a way to share values like theme, user data, or language across the component tree without passing props manually at every level.
Context solves "prop drilling" - passing props through 5+ component levels just to reach a deep child.

How It Works:
• createContext() creates context container
• Provider component wraps tree and provides value
• useContext() reads value in any child component
• Updates to context value re-render all consumers
• Best for global data: theme, auth, language
Context provides data → Any component can access it
⚖️ State vs Props
Key Differences
Definition: State is data managed inside a component. Props are data received from parent. State is mutable, props are immutable.
State: Private to component, can be changed with setState, managed internally, causes re-render when updated.

Props: Read-only, passed from parent, cannot be changed by child, used for configuration.

Rule of thumb: If data changes inside component → use State. If data comes from parent → use Props.
State = internal memory | Props = external input
