Prototypes & Inheritance

Prototypes are how JavaScript does OOP. Every object has a prototype. Every array inherits from Array.prototype. Master prototypes and you understand how `new`, `class`, `extends` actually work under the hood.

🎯 What is a Prototype?

Definition
A prototype is an object that other objects inherit properties and methods from. Every JS object has a hidden `[[Prototype]]` property. When you do `obj.method()`, if method doesn't exist on obj, JavaScript automatically looks for it in obj's prototype. This is called the "prototype chain".

Basic Prototype Example
const person = { name: 'Ali', age: 25 }; // person doesn't have toString method console.log(person.toString()); // But it works! // Why? Because person inherits from Object.prototype console.log(person.__proto__ === Object.prototype); // true
Line 1-4: const person = {}

When you create object literal {}, JavaScript automatically sets its prototype to Object.prototype. This is why every object has methods like toString(), hasOwnProperty(), etc even though you didn't define them.

Line 7: person.toString()

person object doesn't have toString method. JavaScript doesn't give error. Instead it looks up the prototype chain: person → Object.prototype → null. Finds toString in Object.prototype and runs it.

Line 10: __proto__

__proto__ is the property that points to the object's prototype. Every object has it. person.__proto__ is Object.prototype. Object.prototype.__proto__ is null. That's the end of chain.

⚡ Function Prototypes & 'new' Keyword

How 'new' Works
Functions have a `prototype` property. When you use `new` keyword, JavaScript creates new object whose prototype is set to function's prototype. This is how constructor functions work.
Constructor Function Example
function Person(name, age) { this.name = name; this.age = age; } // Add method to prototype - shared by all instances Person.prototype.sayHello = function() { return 'Hello, I am ' + this.name; }; const ali = new Person('Ali', 25); const fatima = new Person('Fatima', 23); console.log(ali.sayHello()); // Hello, I am Ali console.log(fatima.sayHello()); // Hello, I am Fatima console.log(ali.__proto__ === Person.prototype); // true
Line 1-4: function Person()

This is constructor function. When called with new, it creates new object and binds this to it. Without new, this would point to global object and break.

Line 7: Person.prototype.sayHello

Adding method to prototype means all Person instances share same function in memory. If you put sayHello inside constructor, each instance would get its own copy. Waste memory. Prototype = efficient.

Line 11: new Person()

new does 4 things: 1. Create empty object {}, 2. Set obj.__proto__ = Person.prototype, 3. Bind this = obj, 4. Return obj. That's the magic behind new keyword.

🔗 Prototype Chain in Action

How JS Finds Properties
const arr = [1, 2, 3]; // arr doesn't have push method arr.push(4); // But this works! // Prototype chain lookup: console.log(arr.__proto__ === Array.prototype); // true console.log(Array.prototype.__proto__ === Object.prototype); // true console.log(Object.prototype.__proto__ === null); // true // So lookup goes: arr → Array.prototype → Object.prototype → null
Key Insight: Arrays inherit from Array.prototype, which inherits from Object.prototype. That's why arrays have both array methods like push, map AND object methods like toString.

If property not found: JavaScript goes all the way to null. If still not found, returns undefined. No error thrown.

🏗️ Classes Are Just Syntactic Sugar

Class vs Constructor Function
// ES6 Class Syntax class Person { constructor(name) { this.name = name; } sayHello() { return 'Hello ' + this.name; } } // This is EXACTLY the same as: function Person(name) { this.name = name; } Person.prototype.sayHello = function() { return 'Hello ' + this.name; };
Truth: `class` keyword in ES6 doesn't create new inheritance model. It's just cleaner syntax for constructor functions + prototypes. Under the hood, it's still prototypes.

If you don't understand prototypes, you won't understand what `class` and `extends` actually do.
